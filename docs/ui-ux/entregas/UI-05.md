# Entrega UI-05 · Indicadores administrativos

## 1. Identificación

UI-05, 26/11/2026. Estado propuesto: **pendiente de aceptación**. UI-04 aceptada mediante «continua» al autorizar esta etapa.

## 2. Objetivo

Modernizar la presentación de los indicadores y componentes administrativos existentes, manteniendo sus datos, acciones y permisos.

## 3. Alcance

La vista compartida de Reportes y sus errores: indicadores, gráfica existente, filtros, criterios, resultados y navegación. Sin nuevas consultas, cálculos, endpoints o indicadores. No se rediseñan documentos PDF/XLSX.

## 4. Estado inicial

El resumen está en `/reports`; no existe un origen independiente de indicadores para el inicio público. La vista tenía estilos inline y un límite claro de compatibilidad. Línea base: 285 pruebas / 1.167 aserciones; Pint, Larastan y Composer pasan. [Resultados](../qa/ui-05/quality.json).

## 5. Estado Git

Inicio limpio en `main`, HEAD `ee90df7`. Se conserva HEAD; sin staging, commits, pushes, ramas ni despliegue. [Integridad de 3.130 archivos](../qa/ui-05/source-integrity.json).

## 6. Archivos creados

`public/css/ui/reports.css`; `tests/Feature/ReportPresentationTest.php`; fixtures previas, fábrica de datos ficticios y README en `tests/Fixtures/UI05/`; [documentación](../dashboard-ui05.md), este informe y carpetas exclusivas de QA/evidencias de UI-05. Inventario completo en el manifiesto de QA.

## 7. Archivos modificados

`Modules/Reports/resources/views/index.blade.php`, `error.blade.php`, `resources/views/layouts/app.blade.php` y `docs/ui-ux/ESTADO.md`. El layout retira exclusivamente el límite claro para Reportes; lo conserva para POS. Ninguna prueba existente se modifica.

## 8. Justificación

Usar los tokens del Design System para jerarquía de indicadores, campos, tabla y errores; habilitar tema oscuro completo y mejorar foco y legibilidad. La vista compartida aplica la misma presentación a las nueve variantes existentes.

## 11. Accesibilidad

Controles de al menos 44 px, foco visible, tabla y gráfica enfocables, encabezados conservados en el documento, estados vacíos y mensajes existentes. Doce interacciones y cuatro comprobaciones adicionales pasan. Veintiséis pares cumplen: texto mínimo 6,29:1 y no textual 3,29:1. No se certifica WCAG completa.

## 12. Responsive

Chrome en siete resoluciones, de 2560×1440 a 320×844; Edge en escritorio y móvil. Claro/oscuro para seis vistas: 108 casos sin desbordamiento de página, controles sin nombre ni IDs duplicados. Tabla móvil por tarjetas con todos sus campos. Fuente raíz duplicada a 320 px sin desbordamiento. [Matriz](../qa/ui-05/responsive.csv).

## 13. Rendimiento

CSS nuevo de 7.178 bytes sin comprimir; CSS inline anterior retirado. Sin JavaScript, fuentes o paquetes nuevos. LCP local n=5, mediana antes/después 372/316 ms, rangos 280–400/288–412; CLS 0. Muestras solapadas: no se atribuye mejora causal. INP y Lighthouse pendientes.

## 14. Integridad

Diez archivos protegidos y 168 archivos existentes bajo pruebas intactos. Backend, rutas, DTOs, consultas, cálculos, permisos, conexión, exportadores y configuración sin cambios. Scripts funcionales idénticos. Metadatos posteriores: `fresapos_test`, cero tablas. No se ejecutaron pruebas financieras sobre la base operativa ni se calcularon hashes de sus filas.

## 15. Defectos preexistentes

La línea base seleccionada no registra fallos. Se conserva la dependencia CDN y las limitaciones previamente documentadas del entorno. No hay fuente implementada de alertas de inventario, actividad reciente o tendencias adicionales en esta pantalla; se excluyen del alcance.

## 16. Incidencias

No fallaron las pruebas ni la matriz de navegador ejecutadas. Sin rechazos o fallos de revisión automática de permisos en esta etapa. Una búsqueda inicial apuntó a una ruta de infraestructura inexistente; se localizó la estructura real sin modificarla.

## 17. Riesgos

Las pruebas seleccionadas y comparaciones reducen el riesgo sin garantizar ausencia de defectos. Falta revisar conjuntamente autenticación real, renderizado y acciones desde un navegador con datos seguros. Las fixtures no son conciliaciones financieras.

## 18. Limitaciones

Las vistas protegidas se revisan en fixtures sin conexiones SQL; las operaciones se prueban por HTTP contra SQL independiente. Solo Chrome/Edge headless. El «antes» se reconstruye desde Git y recupera su límite claro original dentro del layout compartido. Fuente duplicada no equivale a zoom nativo.

## 19. No ejecutado

Suite global repetida de otras áreas: se eligieron Feature, Architecture y ReportsHttpTest por el alcance. E2E autenticado de navegador, lectores de pantalla, tacto real, Firefox/Safari, zoom nativo, axe/Lighthouse/INP, Azure SQL y cPanel: pendientes por entorno o alcance. No se presenta la suite histórica de UI-03 como resultado de UI-05.

## 20. Criterios de aceptación

Datos y controles comparados con la vista anterior, regresión HTTP de reportes satisfactoria, temas y responsive verificados, documentación e integridad entregadas. Pendientes de accesibilidad integral y E2E autenticado expresamente registrados. Aceptación del responsable pendiente.

## 21. Recomendaciones

Revisar `/reports` con un usuario autorizado, el rango de consulta, indicadores y detalle. Aceptar o solicitar ajustes de UI-05. La siguiente propuesta es UI-06, componentes administrativos existentes; requiere autorización independiente.

## 22. Propuesta de estado final

**Pendiente de aceptación de UI-05.** No se inició UI-06. [Índice](../ESTADO.md).
